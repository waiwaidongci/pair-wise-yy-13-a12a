# 小样送样确认台 · 纺织染整实验室

纺织染整实验室小样送样确认系统。针对「称料与复核由一人补签、染料成本不对预算」的问题，
每张小样确认单强制 **订单 + 配方版本 + 色卡** 三绑定，称料与复核 **双人分别签名**，
成本按实际投料计算；染料余量不足或超出订单预算时一律停在「待处理」，无法生成送样单。

## 业务规则

- **建单**：每个小样绑定客户订单、配方版本、色卡与布样重量，创建即固化主数据快照。
- **称料确认**：称料员逐行登记实际称料量并签名；成本 = Σ 实际投料 × 染料单价（按投料算成本，不按计划）。
- **复核确认**：必须由称料人之外的另一位人签名；同人被引擎拦截，不允许补签。复核可退回重新称料。
- **出单闸门**：染料可用余量（实物库存 − 其他在途单占用）不足，或「订单已出累计 + 本单」超预算 → 停在待处理，禁止出送样单；双签齐全且校验通过才可出单，出单后实际扣减染料库存。
- **变更失效留档**：配方发布新版本、色卡修订或订单预算调整后，相关在途旧确认单自动失效留档（保留快照、原因、审批台账），并生成新版本承接单重新称料出结果；已出单记录不可变。
- **列表核对**：按订单、按状态筛选；展开可核对投料成本、余量、预算占用、两位审批人、版本差异（配方 %/工艺、色卡版本、预算）与完整事件台账。

## 架构（计算 / 档案 / 页面分离）

```
src/
  domain/
    types.ts          # 领域模型
    calculations.ts   # 计算层：纯函数（用量、成本、余量占用、预算、阻断、版本差异）
  archive/
    engine.ts         # 档案层：状态机 + 校验闸门 + 失效留档/承接（纯 step 函数）
    seed.ts           # 初始主数据 + 演示场景引导（全部经引擎动作生成）
    store.ts          # React 适配：localStorage 落档、动作派发
  pages/
    ConfirmStation.tsx# 页面层：确认单列表、筛选、新建
    SheetDetail.tsx   # 页面层：展开核对、双人签名、出单
    MasterData.tsx    # 页面层：染料/预算/配方版本/色卡管理
    meta.ts
  App.tsx
```

## 技术栈

React 19 + Vite + TypeScript（无后端，状态落 localStorage，可一键重置演示数据）
